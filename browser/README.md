# Личное расширение TermVault (Windows)

Экспериментальное заполнение по нажатию, без публикации в магазине.
**Сначала проверяйте на тестовых данных.**

## Установка в Яндекс Браузере

Для готового ZIP без установки Rust см. [краткую инструкцию](QUICKSTART.ru.md).
Мастер `setup.ps1` устанавливает расширение в постоянную папку и регистрирует
выбранный браузер. Для диагностики откройте «Параметры расширения» и нажмите
«Проверить подключение»: `ping` проверяет мост, не открывая хранилище.
Шаги ниже относятся к сборке из исходников.

1. В папке проекта выполните:

   ```powershell
   cargo build --release --locked --target-dir target/browser-build
   ```

   Отдельная папка сборки позволяет не закрывать уже запущенный обычный TermVault.
2. Откройте `browser://extensions` (если нужно — `chrome://extensions`), включите
   режим разработчика → «Загрузить распакованное расширение». Выберите папку:

   ```text
   C:\Users\Andrey\Desktop\termvault\browser\extension
   ```

3. Скопируйте ID расширения (32 буквы) и выполните из папки проекта:

   ```powershell
   .\browser\install.ps1 -ExtensionId 'ВАШ_ID_РАСШИРЕНИЯ'
   ```

   Если база не в стандартном месте:

   ```powershell
   .\browser\install.ps1 -ExtensionId 'ВАШ_ID_РАСШИРЕНИЯ' -Vault 'C:\Vaults\personal.kdbx'
   ```

4. Закрепите кнопку расширения на панели браузера.

Права администратора не нужны. Скрипт копирует программу в
`%LOCALAPPDATA%\TermVault\browser`, записывает конфигурацию **без паролей**,
разрешает подключение одного ID и регистрирует Native Messaging host в
`HKCU\Software\Chromium\NativeMessagingHosts\com.termvault.browser`.
Яндекс Браузер 26.10 использует путь Chromium, а не отдельную ветку Yandex.
Папка моста получает ACL для текущего пользователя и SYSTEM. База не изменяется.
Для Chrome/Edge предусмотрен параметр `-Browser Chrome` / `-Browser Edge`.
Если PowerShell запрещает скрипты, не меняйте глобальную политику безопасности:
сначала проверьте скрипт и используйте разрешённый в вашей системе способ запуска.

## Использование

1. В обычном TermVault заполните у записи **URL**, например `https://example.com/login`.
   Сохраните Ctrl+S. Схема HTTPS, имя хоста и порт должны точно совпадать с сайтом.
   `example.com`, `www.example.com` и `login.example.com` — разные назначения.
2. Откройте HTTPS-страницу с формой входа → нажмите кнопку расширения.
3. В отдельном окне TermVault проверьте адрес и введите мастер-пароль.
   Выберите запись стрелками → **Enter** → **y** в подтверждении. **Esc** отменяет.
4. Логин и пароль вставятся в форму. Кнопку входа нажимаете самостоятельно.

Значок `…` — ожидание; `✓` — заполнено; `!` — отказ/ошибка. Подробность видна
при наведении на кнопку. Запрос ограничен тремя минутами; локальное окно
блокируется после 120 секунд бездействия. Уже открытый терминальный сеанс не
используется: каждое заполнение требует отдельной разблокировки.

Поддерживаются простые формы с одним паролем и однозначным логином, а также
этап входа только с паролем. Если форм несколько, сначала выберите поле пароля.
В MVP не поддерживаются iframe, Shadow DOM, формы без `<form>`, новые пароли,
неоднозначные поля и отправка формы на другой origin.

## Безопасность и ограничения

- Разрешения: `activeTab`, `scripting`, `nativeMessaging`; нет постоянного доступа
  ко всем сайтам, `storage`, файлового доступа, телеметрии или сетевого сервера.
- Браузер и программа проверяют зарегистрированный ID. Запись выбирается только
  для точного HTTPS origin, без совпадений по подстроке и автоматического
  распространения на поддомены. База в режиме подтверждения не редактируется.
- Запрос привязан к исходному документу и полям формы. Навигация, замена полей,
  небезопасный адрес отправки или истечение срока отменяют заполнение.
- Мастер-пароль остаётся в локальном приложении. В браузер поступают только
  выбранные логин и пароль, без заметок, списка записей и остальной базы.
- Связь — Native Messaging и анонимный канал дочернего процесса; TCP-порта,
  локального HTTP API и файлов с расшифрованными секретами нет.

Локальная установка **не делает код некопируемым**. Защита не зависит от тайны
исходников. После заполнения скрипты сайта могут прочитать пароль. Вредоносные
программы с правами пользователя, администратор, дампы памяти и скомпрометированный
браузер остаются за границей защиты. JS-строки и внутренние IPC-копии невозможно
гарантированно обнулить. Это неаудированный MVP, а не гарантия безопасности.

## Обновление и удаление

После сборки новой версии повторите `install.ps1` и обновите расширение на его
странице. Если после переноса папки изменился ID, переустановите мост с новым ID.
Одна конфигурация связана с одним ID и одной базой.

```powershell
.\browser\uninstall.ps1
```

Удаляется только регистрация выбранного браузера; расширение удалите вручную.
Файлы моста сохраняются на случай использования другим браузером. Хранилища и
резервные копии не затрагиваются.

## Проверка и диагностика

```powershell
cargo test --all-targets --locked
node --test browser/tests/*.test.mjs
```

Ручная проверка в браузере обязательна: тестовая HTTPS-форма → разблокировка →
Enter/y → заполнение; затем отмена Esc, неверный пароль, отсутствие подходящих
записей и смена страницы во время подтверждения. DOM-тесты не заменяют эту проверку.

Если мост не найден, проверьте ID, регистрацию, повторную установку после сборки
и поддержку Manifest V3/Native Messaging текущей версией браузера. Корпоративные
политики могут запрещать пользовательские Native Messaging hosts. Не отключайте
защиту браузера ради работы расширения.
