# Первая загрузка в Chrome Web Store

Яндекс Браузер поддерживает совместимые расширения из Chrome Web Store.
Публикация в каталоге не устанавливает Windows-приложение: оно по-прежнему
нужно для открытия локального хранилища. До первой модерации проверьте актуальные
требования и заполните сведения от своего имени — не обещайте аудит безопасности.

## Сначала загрузка черновика, не отправка на модерацию

1. Откройте https://chrome.google.com/webstore/devconsole и войдите в свой аккаунт.
   При необходимости зарегистрируйтесь как разработчик и выполните требуемые
   подтверждения/оплату самостоятельно. Пароли, коды и платёжные данные не передавайте.
2. Подготовьте ZIP из корня репозитория:

   ```powershell
   python scripts/package-extension.py
   ```

3. «Добавить новый элемент» → загрузите `dist/termvault-extension-0.1.0.zip`.
   Имя зависит от версии. **Не загружайте Windows ZIP, EXE или папку с базой.**
   `manifest.json` находится прямо в корне правильного ZIP.
4. Сохраните присвоенный магазином ID расширения (32 буквы a-p). Этот ID нужно
   один раз внести в установщик разработчику: ID распакованной версии не подходит.
   Сохраните существующую карточку — новые версии загружаются в неё же.
5. Пока оставьте карточку черновиком. Перед модерацией необходимы реальный
   скриншот, опубликованная политика конфиденциальности и доступный Windows-релиз.

Не добавляйте случайный `key` в manifest и не генерируйте новые ID для обновлений.
Если потребуется тот же ID для локальной разработки, используйте публичный ключ,
выданный именно этой карточкой магазина. Приватные ключи в Git не добавляются.

## Данные карточки

Название и короткое описание берутся из manifest. Язык: русский.
Категорию выберите по актуальным вариантам каталога, соответствующим управлению паролями.

### Полное описание

TermVault заполняет логин и пароль на HTTPS-странице по вашему нажатию и только
после подтверждения в отдельно установленном локальном приложении TermVault для Windows.

Как работает: нажмите кнопку расширения, проверьте адрес в окне TermVault,
разблокируйте локальное хранилище, выберите запись и подтвердите её передачу.
Кнопку входа на сайте нажимаете самостоятельно. В параметрах расширения доступна
проверка подключения, которая не открывает базу и не требует мастер-пароля.

Мастер-пароль не передаётся расширению. Расширение не загружает базу в облако,
не использует рекламу или аналитику и не запрашивает постоянный доступ ко всем сайтам.
Поддерживаются простые формы входа с точным совпадением HTTPS origin. iframe,
сложные нестандартные формы и формы регистрации могут не поддерживаться.

Важно: без отдельной Windows-программы расширение не заполняет пароли.
TermVault — экспериментальный неаудированный проект. Начните с тестовых данных,
сохраняйте независимые зашифрованные резервные копии. Скрипты сайта могут прочитать
пароль после заполнения формы. Это не защита от вредоносного ПО на компьютере.

Исходники и инструкции: https://github.com/Andrey89711/TermVault

### Privacy practices

Single purpose: заполнение выбранных локальных учётных данных в форме текущего
HTTPS-сайта после явного подтверждения пользователя в TermVault.

Обоснование разрешений:

- `activeTab`: временный доступ к текущей вкладке только после нажатия кнопки.
- `scripting`: проверка формы и заполнение полей в исходном верхнем документе;
  не нужен постоянный доступ ко всем сайтам.
- `nativeMessaging`: связь с локальным TermVault для проверки соединения и
  передачи одной одобренной записи. Мастер-пароль остаётся в нативном приложении.

Remote code: нет. JS поставляется внутри пакета; EXE устанавливается отдельно,
его код не загружается для исполнения внутри расширения.

Политика: https://github.com/Andrey89711/TermVault/blob/main/PRIVACY.md
**Сначала закоммитьте и опубликуйте этот файл; не отправляйте неработающую ссылку.**

Не выбирайте автоматически «не обрабатывает пользовательские данные» только
потому, что нет сервера. Расширение обрабатывает логины/пароли, origin текущего
сайта и структуру формы. Декларации в анкете должны соответствовать действующим
определениям магазина и PRIVACY.md; отсутствие аналитики не отменяет эту обработку.
Проверьте актуальные категории данных (authentication information, URLs/site content)
и подтвердите ограниченное использование только после собственной проверки.

### Изображения

- Иконка 128x128: `browser/extension/icons/icon-128.png`.
- Нужен как минимум **один настоящий скриншот 1280x800** интерфейса/работы расширения.
  Используйте только вымышленные данные; не показывайте реальные пароли, аккаунты,
  вкладки, личные пути или ключи. Не выдавайте макет за скриншот готовой функции.
- Промоматериалы необязательны согласно текущей справке; проверьте требования dashboard.

### Distribution

- **Unlisted**: доступно по ссылке, не показывается в поиске; ссылку можно переслать.
- **Private**: доступ доверенным тестировщикам с Google-аккаунтами. Проверяйте
  установку в Яндекс Браузере отдельно — не предполагайте идентичную работу авторизации.
- **Public**: общедоступная карточка.

Выбор видимости не отменяет модерацию. Для первого теста можно выбрать Private;
для установки обычными пользователями по ссылке — Unlisted. Финальный выбор ваш.

## Инструкция модератору и выпуск

Укажите прямую ссылку на опубликованный Windows x64 релиз и краткие шаги установки.
Не отправляйте на проверку, пока ссылка на программу не работает. Модератор может
создать собственную тестовую KDBX-базу через tvault.exe --create; аккаунта нашего
сервиса нет. Укажите, что нужно зарегистрировать присвоенный магазином ID через
setup.ps1, открыть параметры расширения и проверить соединение, затем проверить
простую HTTPS-форму на вымышленных учётных данных.

После получения ID разработчик обновит установщик для подключения без ручного
ввода ID и открытия страницы магазина. Затем нужно проверить именно магазинную
сборку с локальным мостом и подготовить соответствующий Windows-релиз.
Перед отправкой на модерацию проверьте все сведения; можно отключить автоматическую
публикацию после проверки и опубликовать вручную.
